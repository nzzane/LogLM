LLM & Pipeline Settings

Configure per-tier Ollama instances, models, and escalation thresholds. Changes take effect within 30 seconds — services poll for updates automatically.

Deployment Mode

Choose how Ollama instances are distributed across tiers. Tier URLs below are used when the mode uses separate instances; leave blank to inherit the default URL.

Tier 1 — Fast Categorizer processor

Per-event keep/store/drop classification. Runs on every incoming log line before any deeper analysis. Uses a signature cache so repeated patterns cost near-zero. Recommended: llama3.2:1b, qwen2.5:0.5b.

Tier 2 — Correlation Analyzer analyzer

Batched cross-domain correlation: syslog + SNMP + nginx streams analyzed together. Generates structured alerts and decides when to escalate to Tier 3. Recommended: llama3.1:8b-instruct-q4_K_M, qwen2.5:14b.

Tier 3 — Forensic Engine analyzer

Deep-dive causal chain analysis, historical incident matching, and Pre-Alert report generation. Triggered only for high-confidence, multi-source critical events. Asynchronous — does not block the alert pipeline. Recommended: qwen2.5:32b, llama3.3:70b, or a cloud API.

Chat Model web

Model used for the interactive chat interface. Defaults to the deep (T2) model. Can be overridden to a faster/cheaper model for chat if T2 is resource-constrained.

Current Environment Values

Read-only. These are the values active when the containers started. Settings above override these at runtime; a restart applies both.
